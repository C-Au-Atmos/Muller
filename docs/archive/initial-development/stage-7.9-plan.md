# Stage 7.9 - Windows 文件管理交互与 Duplicate 工作流加固计划

状态：Stage 7.9.0-7.9.6 实现和自动化验收完成；Stage 7.9.7 物理环境验收待完成  
计划日期：2026-07-25  
前置条件：Stage 7 自动化验收完成  
后续阶段：Stage 8 特权 MFT/USN 索引器  
验收报告：[Stage 7.9 执行与验收报告](stage-7.9-report.md)

## 1. 阶段结论

这批反馈不是一组可以逐个打补丁的 UI 问题。它们共同依赖四个当前尚未成立的
产品基础：

1. 文件选择仍是单个数组下标，不是 Windows 资源管理器式的稳定文件集合；
2. Duplicate 只有扫描器建议，没有用户决策、批量选择和清理复核模型；
3. 普通路径、Windows 虚拟位置和用户显示路径没有统一边界；
4. 预览仍通过有大小上限的整文件 Base64 传输，无法扩展成专业媒体预览。

因此 Stage 7.9 必须先完成共享状态和协议，再交付表层交互。否则会出现“界面框选
了十个文件，但复制或清理只处理一个”的危险半成品。

Stage 7.9 的产品目标是：Muller 在 Browse、Album 和 Duplicates 中具备一致的
Windows 文件管理操作逻辑，同时保留现有的虚拟化、任务隔离、回收站安全检查和
动画性能边界。

## 2. 当前实现与反馈分析

| 领域 | 当前实现 | 反馈背后的根因 | Stage 7.9 决策 |
|---|---|---|---|
| Browse/Album 选择 | 每个面板只有一个 `selectedPosition` | 没有选择集合、锚点、焦点项和稳定文件身份 | 建立按路径保存的每面板选择模型 |
| Masonry 方向键 | 按数组 `+/-1`，左右键用于切换面板 | 数据顺序与视觉邻居不是同一关系 | 按布局几何寻找上下左右邻居，面板切换移至组合键 |
| Masonry 自动滚动 | 直接写入 `scrollTop`/`scrollLeft` | 选中半露出的图片时产生硬跳 | 最小距离、可重定向的平滑露出滚动 |
| 鼠标多选 | 只有单击单选 | 无 Ctrl、Shift、框选和边缘自动滚动 | 对齐 Windows 资源管理器选择语义 |
| 弹簧选框 | Grid/Album 和 Duplicate 部分使用弹簧，List/Diff 为静态 | 动画所有权和生命周期不统一 | 多选底色静态，仅焦点框弹簧；做全视图闭环测试 |
| Duplicate 性能 | 文件发现后，head/tail 指纹阶段串行，完整哈希才使用 Rayon | 4.6 万文件时“后面的比较”可能被串行快速指纹和磁盘访问拖慢 | 先分阶段测量，再做有界、存储友好的并发 |
| Duplicate 结果 | 完整扫描报告生成后才逐组发送给前端 | 用户在全部比较完成前看不到已确认结果 | 支持稳定组 ID 和渐进式结果，同时保持最终确定排序 |
| KEEP/DUP | `suggested_keep` 是扫描器唯一决定 | 建议值被界面表现成最终决定 | 区分“建议”和“用户确认”，允许右键及多选修改 |
| Duplicate 日期 | 已采集修改时间，但列表不展示；没有创建时间 | 路径记忆和复制时间无法参与人工判断 | 展示创建/修改日期，提供日期排序和建议策略 |
| Duplicate 清理 | 只能清理当前一个 DUP；清理后重新扫描整个根目录 | 缺少批量复核，且清理后再次承受完整扫描成本 | 增加清理清单、总量确认和局部结果协调 |
| 扫描路径 | 纯文本输入 | 普通用户必须理解 Windows 路径语法 | 原生目录选择器为主，文本输入保留为高级入口 |
| `\\?\` 路径 | Browse 部分调用 `displayPath`，其他页面直接渲染原始路径 | 清洗逻辑分散在页面 | 统一内部路径与显示路径边界，全局禁止直接渲染内部路径 |
| 顶部地址栏 | 只接受完整路径并在 Enter 后导航 | 没有子目录候选和 Tab 补全会话 | 增加可取消、可键盘操作的路径补全 |
| 左侧列表 | 快捷位置硬编码；`Favorites.path` 永远等于当前 tab 路径 | 任意目录都会被错误表现成 Favorites | 删除伪 Favorites，改成用户明确固定的位置 |
| This PC | 硬编码为 `D:\` | 它不是虚拟位置，也不能列出所有磁盘 | 建立类型化虚拟位置并枚举 Windows 卷 |
| 文档/图片等目录 | 写死 `D:\Pictures` 等路径 | 无法处理 C/D 迁移、OneDrive 和用户重定向 | 通过 Windows Known Folder API 获取真实位置 |
| Filters | 后缀列表硬编码为十种 | 与当前目录内容无关 | 后端聚合当前完整目录会话中的后缀和数量 |
| Cubes | `Cubes strip/grid` 名称抽象，普通 Browse 不加载真实缩略图 | 视图差异不清晰，视觉模式没有文件管理价值 | 产品名改为 Filmstrip/Large icons，并加载真实预览 |
| Preview | 仅图片/文本；图片 4 MiB 上限；元数据很少 | 整文件 Base64 IPC 模型无法支持大图、音频和视频 | 改为流式/缩放预览与结构化专业元数据 |
| Flow Border | 状态由全局 Duplicate 会话派生，扫描完成后会长期处于白色 success | 任务状态没有限定到 owner tab 和当前模式 | 建立有作用域、有超时的视觉状态机 |
| Flow Border 位置 | Canvas 覆盖整个 WebView 边缘 | 发光会向内容区内侵 | 移至不接收输入的外缘带，不覆盖正常内容 |
| 全局按钮 | 常用按钮多为 27-32px | 鼠标目标偏小，紧张且容易误点 | 默认提高到 36-40px，并重新验证窄窗口布局 |

已有修正作为本阶段基线保留：release GUI 子系统不弹命令行、Album 滚动不再卸载
整个界面、Line Sidebar/Option Wheel 的 RAF 可重复启动，以及 Album 当前选框的基础
弹簧动画。Stage 7.9 负责防回归和补全行为，不重复实现这些修正。

## 3. 统一交互合同

### 3.1 选择模型

每个 Browse 面板和 Duplicate 结果页保存：

- `selectedKeys`: 稳定路径键集合；
- `anchorKey`: Shift 范围选择起点；
- `focusKey`: 当前键盘焦点和预览目标；
- `selectionIntent`: replace、toggle、range 或 marquee；
- `revision`: 目录刷新后用于协调已消失条目的数据版本。

路径是文件操作键，不再用虚拟列表位置作为长期身份。刷新、过滤、排序和切换视图
后按路径保留仍存在的选择；不存在的项从集合中移除。预览、打开和重命名作用于
`focusKey`，复制、剪切、回收和 Duplicate 标记作用于完整选择集合。

Windows 式选择行为固定为：

- 普通单击替换选择；
- Ctrl+单击切换单项；
- Shift+单击从锚点连续选择；
- Ctrl+A 全选当前查询结果；
- Shift+方向键扩展范围；
- Ctrl+Space 切换焦点项；
- 单击空白处清空；
- 空白处拖动超过阈值后开始框选；
- 靠近视口边缘时自动滚动并继续命中未挂载的虚拟化项目；
- 在已选文件上拖动时保留给文件拖放，不误启动空白框选；
- 右键已选项保留整个集合，右键未选项才替换选择。

多选项使用静态选中底色，只有 `focusKey` 的主轮廓使用弹簧移动。这样既能看清
集合，也不会让几十个选框同时弹动。

### 3.2 Masonry 和其他视图的方向键

Masonry 不使用数组下标推导方向：

- 上/下：优先同一视觉列的前一个或后一个项目；
- 左/右：进入相邻列，先比较垂直重叠量，再比较中心点 Y 距离；
- 候选完全并列时使用稳定位置键决胜，保证相同布局下结果可重复。

Large icons 使用左右 `+/-1`、上下 `+/-列数`。Filmstrip 以左右为主，上下不离开
当前内容。List 使用上下。左右方向键不再隐式切换面板，面板切换使用
Ctrl+Left/Right，并保留清晰的活动面板边界。

自动滚动只移动让目标完整露出的最小距离，四周保留小幅 reveal margin。连续按键
必须重定向同一个滚动目标，不能把多个浏览器 `smooth` 动画排队。系统启用减少动态
效果时改为即时最小滚动。

### 3.3 Duplicate 决策与清理

每个重复文件的决策状态为：

- `suggested_keep`: 扫描器建议保留，但用户尚未确认；
- `keep`: 用户明确保留；
- `duplicate`: 用户明确加入待清理；
- `undecided`: 没有足够依据，不进入清理。

一个组允许保留多份，但不允许所有物理文件都成为 `duplicate`。硬链接仍按物理身份
处理，不能把移除一个硬链接别名错误计算成释放完整文件空间。

右键菜单提供“标记为 KEEP”和“标记为 DUP”，并作用于多选集合。工具栏提供两个
含义明确的批量命令：

- “采用建议”：把扫描器建议转换为当前决策；
- “选择全部待清理 DUP”：选择所有已经确认的 DUP，不把未确认建议混入清理。

“清理选中项”首先打开复核列表。列表按组展示文件名、可读路径、创建时间、修改
时间、大小、硬链接状态和预计释放空间，允许逐项移除。确认后只移入回收站，不做
永久删除；后端在提交前重新校验路径、大小和 BLAKE3，部分失败逐项报告。清理成功
后先从当前稳定组中协调已移除条目，不强制立即对 4.6 万文件做完整重扫；用户可
主动重新扫描，后台轻量校验作为后续优化。

日期不再只是隐藏字段。组内默认同时显示 Windows 创建时间和修改时间，并允许按
两者及路径排序。创建时间通常能反映“这一份何时被复制到当前位置”，修改时间反映
内容最后编辑时间，两者不能互相替代。自动建议可以提供“优先旧修改时间”“优先新
创建时间”“优先固定目录”等策略，但任何策略都只是建议，不覆盖用户决定。

### 3.4 Windows 路径与虚拟位置

内部文件操作继续保留 canonical/verbatim path，以支持 Windows 长路径。所有可见
文本、title、状态栏、搜索结果、错误提示和确认列表必须通过同一个显示路径转换，
把 `\\?\D:\...` 显示为 `D:\...`，把 `\\?\UNC\server\share` 显示为
`\\server\share`。不能为了显示而修改传给文件操作后端的真实路径。

This PC 不伪装成磁盘路径。导航目标改为类型化联合：

- `directory`: 普通文件系统路径；
- `this-pc`: Windows 虚拟根；
- 后续可扩展 `network`、`recent`，本阶段不提前暴露空入口。

This PC 页面通过 Windows API 枚举磁盘名称、卷标、文件系统、总容量和剩余空间；
双击磁盘后才进入普通目录路径。

Desktop、Documents、Downloads、Pictures、Music、Videos 和用户主目录通过 Windows
Known Folder API 解析。Muller 不猜测它们在 C 盘还是 D 盘；如果用户把 Documents
重定向到 D 盘或 OneDrive，左栏必须显示系统当前真实位置。

Favorites 改成持久化的用户固定项，只有用户执行“固定到左侧栏”才出现。当前目录
不属于任何快捷位置时，左栏允许没有选中项，不能回落到 Home 或 Favorites。

### 3.5 Preview 和缩略图

图片不再因文件大于 4 MiB 被拒绝。新的预览通道不把完整文件 Base64 编码后塞进
IPC，而是采用后台解码、按视口缩放、可取消请求和有界缓存。这里的“没有限制”定义
为“不按源文件字节数拒绝正常图片”；损坏文件、解压炸弹和异常像素尺寸仍必须用
解码预算保护进程，并尽量返回缩放预览而不是简单报错。

音频和视频使用可 seek/range 的本地流，不把整个媒体文件读进前端内存。文本文档
允许截断，并明确显示已加载范围及打开原文件入口。

专业元数据至少包括：

- 通用：精确字节数、创建/修改/访问时间、属性、扩展名、MIME、文件系统路径；
- 图片：像素尺寸、方向、位深、色彩空间、ICC、DPI、EXIF/XMP/IPTC、相机、镜头、
  曝光、ISO、焦距、拍摄时间和存在时的 GPS；
- 音频：容器、编码、时长、码率、采样率、声道、位深、标题、艺术家、专辑、曲号、
  年份、流派和封面；
- 视频：容器、视频/音频编码、时长、分辨率、帧率、码率、旋转、色彩/HDR 信息、
  音轨和存在时的标题标签。

优先使用 Windows Property System/Media Foundation 获取系统已支持格式的通用字段，
再用经过验证的解析库补齐格式专有元数据；不依赖用户另行安装 `ffprobe.exe`。

Filmstrip 和 Large icons 沿用当前内部 presentation ID 以兼容已保存工作区，但产品
界面不再显示难懂的 Cubes strip/grid 名称。两种视图都遵守相同选择、右键、拖放和
键盘合同。可预览文件渲染真实缩略图：图片用图像管线，音频优先封面，视频使用首帧
或 Shell 缩略图，文档使用 Windows Shell 缩略图；只为虚拟化可见窗口发起请求。

### 3.6 Flow Border、进度和按钮

Flow Border 状态机按作用域计算：

- Duplicate 扫描只在 owner tab 当前可见且处于 Duplicates 时使用扫描态；
- 切换到 Browse 后立即回到普通 workspace 态，后台扫描只在 tab 徽标显示；
- 成功和错误是短暂 pulse，结束后自动回到 idle，不形成永久白光高速旋转；
- 隐藏、最小化和减少动态效果继续停止或降级动画。

WebView 内容无法越过 Windows 窗口边界绘制；若字面意义上绘制到系统窗口外部，需要
额外透明伴随窗口并处理 DPI、焦点、点击穿透和多显示器同步，风险远大于收益。本阶段
把“外面”定义为应用内容盒之外的 2-4px 非交互外缘带：跑马灯不覆盖标题、列表或
状态栏，也不挤压工作区内容。只有实机原型仍无法满足观感时，才另立伴随窗口技术
验证，不把它隐含进本阶段。

Duplicate 进度保留现有数字平滑跳动，并增加三段真实阶段：发现、快速指纹、完整
校验。总进度必须单调，阶段切换不能回退；显示当前阶段、处理数、候选数、读取量、
吞吐和可计算时的 ETA，不伪造未知总数。UI 事件更新限频，避免大量进度消息拖慢
主线程。

全局鼠标目标以 36px 为最低默认，主要命令和高频工具栏目标为 38-40px；图标按钮
保持正方形，熟悉命令继续使用图标和 tooltip。窄窗口通过 overflow 和响应式收纳
解决，不把按钮重新压回难点击尺寸。键盘和焦点可见性不能因增大鼠标目标而退化。

## 4. 子阶段与交付顺序

### Stage 7.9.0 - 基线、协议和可观测性

执行状态：完成（2026-07-25）。

范围：建立 46,000 文件基准、按阶段耗时/吞吐遥测、稳定路径键、全局显示路径 API、
视觉状态机和批量命令协议草案。

退出条件：

- 在同一台机器记录现版本 cold/warm 的发现、指纹、完整哈希和结果传输耗时；
- 建立高重复小文件、低重复混合文件和大文件三种压力数据集；
- 所有用户可见路径入口有清单和自动化测试，`\\?\` 不再依赖页面临时处理；
- 选择、决策和批量回收的数据合同通过 reducer/protocol 单元测试。

### Stage 7.9.1 - Explorer 选择、方向键和滚动

执行状态：完成（2026-07-25）。

范围：共享选择 reducer、Ctrl/Shift/Ctrl+A、Masonry 几何导航、各 presentation
方向键、最小平滑露出滚动、拖拽框选、边缘自动滚动和批量 Browse 操作。

退出条件：

- List、Large icons、Filmstrip、Album 对同一输入产生各自正确的视觉邻居；
- 连续按住方向键时选择不落后于滚动，松开后目标完整可见；
- 100,000 项虚拟化夹具中框选不要求挂载所有 DOM 节点；
- 刷新、过滤、排序和切换视图按路径保留有效选择；
- 复制、剪切、回收对完整集合执行，重命名/打开/预览只作用于焦点项；
- 选择 reducer 和端到端测试覆盖 Windows 修饰键语义。

### Stage 7.9.2 - Windows 导航外壳

执行状态：完成（2026-07-25）。

范围：原生目录选择器、地址栏 Tab 补全、This PC 虚拟页、Known Folders、真实
Favorites、全局路径显示清洗。

退出条件：

- Duplicate 可通过 GUI 添加/移除一个或多个扫描根，手输路径仍可用；
- 地址栏聚焦时 Tab 完成候选，Escape 关闭候选，Enter 导航，过期请求不能覆盖新输入；
- This PC 列出实机所有可用卷，进入卷后回到普通分页目录会话；
- Known Folder 路径与 Windows Shell 一致，包括重定向和 OneDrive 场景；
- 当前目录不是快捷位置时左栏没有伪选中，固定项跨启动保存；
- 所有页面、弹窗、title 和状态栏均不显示 verbatim prefix。

### Stage 7.9.3 - Duplicate 性能和渐进结果

执行状态：完成 warm 基准和实现；cold-cache/HDD 实机回归待 Stage 7.9.7 补齐。

范围：优化串行 head/tail 阶段、存储友好的有界并发、渐进组事件、稳定组 ID、
分阶段高级进度和取消检查。

退出条件：

- 在指纹阶段占基线总耗时 30% 以上的 46,000 文件夹具中，同机 warm p50 至少改善
  25%，且 cold/HDD 型顺序读取场景不得回退超过 10%；
- 并发数有硬上限，内存、文件句柄和每任务缓冲区有测量记录；
- 第一个完整验证的重复组在可发送后 1 秒内出现在 UI，不等待全部组结束；
- 最终组顺序确定，渐进更新时选择通过稳定组/路径键保持，不因重排跳到别的文件；
- 扫描期间主线程输入/滚动任务 p95 保持在现有 3ms 预算内；
- 任一阶段取消后不再发送陈旧进度或组事件。

Stage 8 的 MFT/USN 索引器仍能进一步缩短“发现”阶段；Stage 7.9.3 只优化无需提权
的现有遍历和比较漏斗，不能把 Stage 8 当作本阶段性能验收的前提。

## 6. 风险与明确边界

| 风险 | 等级 | 控制方式 |
|---|---|---|
| 多选 UI 与单项后端操作不一致 | 极高 | 先升级选择/批量协议，禁止视觉先行 |
| 批量清理误删 | 极高 | 用户确认决策、复核清单、至少一份保留、哈希复验、回收站 |
| 大媒体导致内存爆涨 | 高 | 流式读取、后台缩放、range、取消、有界缓存，不做整文件 Base64 |
| 并行指纹拖慢 HDD | 高 | 同盘有界并发、cold/HDD 回归门槛、硬上限和遥测 |
| 虚拟路径误传给文件系统 API | 高 | 类型化 LocationTarget，This PC 不使用伪字符串路径 |
| 框选破坏虚拟化预算 | 中高 | 用布局坐标命中，不依赖已挂载 DOM |
| Windows 元数据格式差异 | 中高 | Property System 基线、成熟解析库、缺失字段显式回退 |
| 外窗跑马灯实现扩大窗口复杂度 | 中 | 本阶段限定为内容外缘带，伴随窗口另立验证 |
| 增大按钮导致窄屏溢出 | 中 | overflow 收纳、多视口截图和 hit-target 自动检查 |

本阶段不包含永久删除、无复核的自动清理、写入媒体元数据、完整 Office/PDF 编辑器、
递归 Filter 搜索，以及 Stage 8 的提权服务。预览中的资源保护不是产品文件大小限制；
它是防止恶意或损坏媒体耗尽进程资源的必要运行时边界。
