## `REQ-0.1.5-002` - Space Sniffer 风格的高性能空间方块视图

### 评审输入

- 原始输入：[`01-original-input.md#req-0-1-5-002`](01-original-input.md#req-0-1-5-002)

- 设计附件：[Space Sniffer 空间视图线框](design/space-sniffer-wireframe.svg)
- 交互流程图：[Muller V0.1.5 Space Sniffer Interaction Flow](https://www.figma.com/board/SxWYnaNaS31cnTHtlOLvGY?utm_source=other&utm_content=edit_in_figjam&oai_id=&request_id=948d8780-8eaa-4566-a601-4285c406cf8a)
- 评审日期：`2026-09-12`
- 参与人：`Codex`
- 当前结论：`Accepted`
- 优先级：`P1`
- 目标版本或重审条件：`V0.1.5；补齐规模、性能目标和视图入口后进入 Accepted`

### 价值与范围判断

- 用户价值：用空间比例直接发现大目录、大文件和空间异常，减少逐层打开目录的时间。
- 问题影响：递归扫描和大规模矩形绘制同时涉及磁盘 I/O、线程、内存和交互帧率，若没有渐进式架构容易卡住主界面。
- 当前版本范围：`空间视图入口、首层及递归子层 treemap、渐进统计、方块钻取、鼠标/键盘/选框选择、细分隔线与正交拐角、音效事件、取消和错误状态。`
- 非目标：不读取文件内容；不跟随符号链接；不实现跨磁盘比较、自动清理或 SpaceSniffer 品牌视觉复制。
- 依赖与阻塞：测试版先限定为单栏当前目录、本地可读路径和逻辑字节数；典型规模、性能预算和双栏支持在基准阶段补充，不阻塞原型实现。

### 技术评审

- 扫描架构：Rust 后台会话一次递归枚举元数据，使用有界并行和批量事件推送 `discovered/partial/completed/failed`，支持取消、背压和扫描代次。
- 数据语义：默认统计 logical bytes；协议中的字节数使用字符串或 BigInt 安全表示；符号链接和 junction 默认不跟随，权限失败保留错误节点。
- 缓存策略：以规范化路径、文件 ID（可用时）、大小、修改时间和目录版本校验；缓存只用于增量和钻取首屏，不能替代最终扫描。
- 布局与绘制：使用确定性的 squarified 或 slice-and-dice treemap；布局在 worker 或 Rust 侧计算；Canvas/WebGL 批量绘制方块、1px 光线和 90°正交边界，DOM overlay 提供键盘和 ARIA。
- 交互：单击选择，双击或 Enter 打开目录，Esc/面包屑返回；拖拽选框命中可见矩形；小块聚合或只显示悬浮详情。
- 视觉基线：依据 0.1.4 实机 Platinum 截图，使用 `#09090b`、`#121215`、`#151518`、`#27272a`、`#2f2f35` 和 `#ffffff`；方块只做灰阶层次，细线和选框使用白色，状态色仅用于扫描/错误小提示。
- 音效：复用 `useInterfaceAudio` 的 tick/action/navigate/success/warning 和限流；新增 tile 事件必须去重，扫描异常不得误报成功音效。
- 性能风险：网络盘、机械盘、权限错误、目录持续变化和百万级文件会产生长尾；必须展示扫描状态，限制并发和内存，并允许立即停止。
- 测试策略：Rust 统计/取消/错误测试，面积守恒和稳定布局测试，Canvas/WebGL 选框命中测试，音效节流单测，Windows 基准和 Edge E2E。
- 替代方案：纯前端逐项 IPC 或纯 DOM 方块都会放大 I/O 和布局成本，因此先验证 Rust 扫描 + 批量事件 + Canvas/WebGL。

### 版本决策

- 是否延期：`No`
- 决策理由：先交付可运行测试版验证数据流、空间比例、钻取和交互，再用基准数据收敛高性能指标。
- 测试版边界：

  - [ ] 首批结果可增量出现，扫描可取消，旧会话不会覆盖新会话。（2026-09-13 实测纠正：beta.1 前端等待 Done，增量显示未验收，由 BUG-0.1.5-001 修复。）

  - [ ] 典型目录规模、网络盘、双栏比较和最终 FPS/内存门槛进入后续基准评审。

  - [ ] 方块面积与已统计字节数成比例，部分结果和未知项有明确表示。

## `REQ-0.1.5-004` - 实现 MFT/USN 原生索引并交付测试版 EXE

- 结论：`Accepted`，优先级 P1，目标 V0.1.5，2026-09-13；依据用户明确推进实现的指示。
- 测试版验收状态：`Passed / 0.1.5-beta.1 delivered`；首次构建的两个空间发布阻断已在 `feat/0.1.5` 修复，全部门禁通过并按顺序提升 `release/0.1.5`，重新打包后的实际 EXE 原生索引与空间交互复验通过。构建来源、最终校验值及首次构建历史证据见 [`03-execution.md`](03-execution.md#req-0-1-5-004)。本结论针对下述测试版范围，不代表已完成 Everything 的完整能力或所有磁盘性能验收。
- NTFS 使用只读卷句柄、FSCTL_ENUM_USN_DATA 首次枚举 MFT 记录，FSCTL_QUERY_USN_JOURNAL / FSCTL_READ_USN_JOURNAL 维护变更；记录 file ID、parent ID 与名称，目录重命名必须影响后代路径。
- 捕获枚举前的 USN 水位并重放期间变更；journal ID 变化、水位丢失或不支持的记录版本触发重建或明确降级。不得静默发布不完整卷索引。
- 普通权限界面保留；同一 EXE 的独立索引进程通过 UAC 启动，使用限制本机及用户访问的命名管道。此测试版采用按需进程，不要求安装常驻 Windows SCM 服务。
- 界面必须显示索引引擎、构建/就绪/降级状态与原因，并提供启动原生索引操作。用户取消 UAC 或非 NTFS 路径采用可取消遍历降级。
- 文件名查询复用内存索引，禁止每次读取整个 JSON 或对全盘逐项 stat；尺寸与时间按命中结果补充，不能把 MFT 枚举的文件名记录当作完整空间统计。
- 空间视图保留逻辑字节扫描、钻取、选择和音效。测试包需标注原生文件名索引与空间字节统计的边界。
- 验收：解析异常/重命名/删除/日志断档/取消测试、查询与分页回归、真实 NTFS 原生枚举及变化验证（权限不足必须如实记录）、全套质量门禁、release/0.1.5 上测试版版本信息与 EXE/SHA256。

### 测试版边界与验证记录（2026-09-13）

- 原生 helper 在内存保存 MFT 记录和 USN 水位；每次重新启用会重建，运行期间只重放 USN。此前 JSON 为 portable 降级快照，不能标注为原生持久化。
- FSCTL_ENUM_USN_DATA 提供每个文件记录的主要名称；其他硬链接别名尚未完整覆盖。该边界在应用索引详情及测试包说明中明确展示。
- 查询缓存最多四份，共 200k 条/64 MB；按文件名匹配，不对所有记录 stat；显式按大小/时间排序或按时间过滤时补读匹配候选的元数据。
- 已完成真实 F 盘提权 helper 验证：20,387 条记录，构建含启动/授权耗时 2,047 ms，调试版查询含 IPC 16.675 ms；创建、文件改名、父目录改名、删除均经 USN 收敛。这是单机单盘样本，不能推广为所有磁盘的性能承诺。
- 首次构建 `0.1.5-beta.1` EXE 的 D 盘探针通过：169,001 条记录，初建含进程启动/授权 2,717 ms，首次查询含 IPC 15.9 ms；已有文件的 MFT 枚举和 USN 创建、文件改名、父目录改名、删除均验证通过。
- 首次构建 GUI 实机启用后，5 个磁盘、2,099,823 条记录显示就绪；截图 `native-index-ready.jpg` 随测试包保存。该条证明普通权限 GUI 与独立原生索引进程的完整启动链路，不能据此推断百万级查询耗时。
- 首次构建 GUI 从 C 盘浏览页面执行全盘搜索，可查到 D 盘测试包的 EXE；`native-global-search.jpg` 记录返回结果。空间视图实机打开 `D:\Muller\release`，206 MB、4 个文件夹完成渲染，单击目录的白色选框及属性显示正常。
- 首次构建质量门禁：147 个 Rust 测试、86 个前端测试、92 个 Edge E2E，以及 lint、生产构建、Rust fmt/clippy 通过。另 1 个要求提权的直接 provider 测试保持 ignored，由同 EXE 的真实提权 helper 探针补充验证；修复后的门禁结果见下文。

## `REQ-0.1.5-009` - Portable NTFS 索引持久化、增量校正与空间加速

- 评审日期：`2026-09-19`；结论：`Accepted`；优先级：P1；目标：`0.1.5-beta.7`。
- 技术决策：沿用现有 native helper 的 MFT/USN 记录和卷身份，在 portable 可写目录保存版本化快照、USN journal ID/next USN 和校验信息；使用临时文件 + rename 原子提交。启动先加载可验证快照，再按水位重放 USN；断档、卷序列号变化、格式版本不兼容或权限失败时显式降级并重建。
- 空间集成：空间扫描读取索引目录项和逻辑大小作为首批候选，仍执行可取消的校正遍历并以最新扫描结果覆盖，避免将旧索引当作最终大小。
- 风险与边界：NTFS 以外的卷继续使用原有遍历；便携目录只读、磁盘空间不足和写入冲突必须保持可运行；索引不含内容、不跨用户或卷复用。
- 验收：重启后索引可复用；创建/改名/删除文件后下次启动只处理 USN 增量；模拟断档/损坏后自动重建；空间首批延迟和遍历次数有对比基准，结果与安全遍历一致。

### 实现细化（2026-09-19）

- 当前 MFT provider 保存名称、父文件 ID、属性和 USN，不包含文件长度；因此 beta.7 的空间加速采用“普通权限完整测量缓存 + NTFS 子树变更戳”。匹配时立即显示缓存预览，同时照常遍历校正，完成后整体替换。只加速重复访问首屏，不承诺首次扫描或最终遍历次数减少；直接从 MFT 提取文件大小另行推进。
- 空间缓存限制节点数、文件字节数和保留数量，损坏、变更戳不匹配、不完整扫描均不用作预览；最终大小和可访问对象始终由普通权限扫描决定。
- NTFS 快照优先位于 EXE 旁 `Muller-data/native-index-v1/<用户 SID>`，不可写时回退当前用户 LOCALAPPDATA。helper 使用已认证 GUI 的普通用户令牌读写固定缓存位置，不接受 IPC 任意写入路径。成功启用后记忆磁盘范围，启动仅恢复一次；停止索引关闭下次自动恢复，取消 UAC 不循环请求。
