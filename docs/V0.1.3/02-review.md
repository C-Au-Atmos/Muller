## `REQ-0.1.3-001` - 关闭主窗口行为可选

### 评审输入

- 原始输入：[`01-original-input.md#req-0-1-3-001`](01-original-input.md#req-0-1-3-001)
- 历史 ID：`MUL-LIFE-001`
- 评审日期：`2026-08-13`
- 参与人：`需求提交人（姓名未记录）；文档整理人；技术负责人 TBD`
- 当前结论：`Accepted`
- 优先级：`P0`
- 目标版本或重审条件：`V0.1.3`

### 价值与范围判断

- 用户价值：把关闭窗口从固定隐藏改为可预测、可持久化的用户选择，同时保留托盘
  驻留工作流。
- 问题影响：所有使用主窗口关闭入口的用户都会遇到；当前无法通过设置改变行为。
- 当前版本范围：Settings 的“启动与关闭”分组、主窗口等价关闭请求、托盘退出、
  默认值与恢复默认、持久化和中英文错误状态。
- 非目标：不新增退出确认；不改变最小化按钮、子窗口、系统窗口、失焦行为和现有
  全局快捷键；不重新定义后台扫描与文件操作合同。
- 依赖与阻塞：需要前端设置状态与 Rust 原生窗口事件使用同一已持久化值；写入
  失败时必须保留之前生效的选择。

### 技术评审

- 建议技术栈：React 19、TypeScript、Tauri 2 command/window event、Rust、JSON
  配置持久化和现有 i18n。
- 预计改动模块：`src/features/settings/`、`src/features/lifecycle/`、
  `src/preferences/`、`src/i18n/`、`src-tauri/src/lifecycle.rs`、
  `src-tauri/src/lib.rs`、前端单元测试和 `e2e/`。
- 数据或接口变更：增加 `hide | quit` 关闭行为；提供读取和写入原生状态的 Tauri
  command；旧数据、未知枚举或损坏设置回退为 `hide`。
- 性能与资源影响：设置读取与写入为低频小文件 I/O；关闭事件只读取内存状态，
  不应引入可感知延迟。
- 安全与文件操作风险：配置写入失败、前后端状态漂移或错误拦截系统退出可能导致
  用户误以为应用已退出，或阻断注销、关机和更新退出。
- 测试策略：偏好解析和持久化单元测试；Tauri command 与关闭事件集成测试；
  `X`、`Alt+F4`、任务栏关闭、托盘退出及恢复默认的 Windows 人工测试。
- 替代方案：仅使用 WebView `localStorage` 无法保证原生关闭事件读取到可靠的最新
  值；每次关闭弹确认框不符合“不新增确认流程”的范围，均不采用。

### 版本决策

- 是否延期：`No`
- 决策理由：这是主窗口生命周期的基础控制，范围明确，可复用现有设置、托盘和
  Tauri 窗口事件；来源已给出完整默认值、失败回退和验收行为。
- 验收条件：
  - [ ] “隐藏到系统托盘”为默认值，切换后下一次关闭立即生效，重启后保持。
  - [ ] `X`、`Alt+F4` 和任务栏关闭在两种选项下行为一致。
  - [ ] 隐藏时 PID、托盘、全局快捷键、工作区和允许的后台任务保持；恢复同一窗口。
  - [ ] 退出时走正常退出流程并释放托盘和全局快捷键；再次启动为冷启动。
  - [ ] 托盘“Quit Muller”始终真正退出，Windows 注销、关机和更新退出不被拦截。
  - [ ] 损坏设置和写入失败不会阻止启动或错误切换当前生效行为。

## `REQ-0.1.3-002` - 当前用户登录时自动启动

### 评审输入

- 原始输入：[`01-original-input.md#req-0-1-3-002`](01-original-input.md#req-0-1-3-002)
- 历史 ID：`MUL-LIFE-002`
- 评审日期：`2026-08-13`
- 参与人：`需求提交人（姓名未记录）；文档整理人；技术负责人 TBD`
- 当前结论：`Accepted`
- 优先级：`P1`
- 目标版本或重审条件：`V0.1.3`

### 价值与范围判断

- 用户价值：由用户自主决定登录后是否让 Muller 静默驻留，并确保设置页展示的是
  Windows 实际状态。
- 问题影响：希望长期使用托盘和快捷唤出的用户当前必须每次手动启动；应用也缺少
  对注册失败、升级路径变化和卸载残留的处理。
- 当前版本范围：当前用户自启动开关、隐藏且不抢焦点的登录启动、手动显示意图
  优先、实际注册状态同步、错误回滚、路径刷新和卸载清理。
- 非目标：不实现所有用户或管理员级自启动、计划任务、登录前服务、延迟启动、
  看门狗、退出后重启或安装器 UI 重设计。
- 依赖与阻塞：依赖 Windows 当前用户注册表权限、可靠区分 `--autostart` 与手动
  启动、单实例能力以及 NSIS 卸载钩子；注册表实机验证必须在可恢复的测试账号进行。

### 技术评审

- 建议技术栈：React/TypeScript 设置 UI、Tauri 2 command、Rust `winreg`、
  Windows `HKCU` Run/StartupApproved 状态和 NSIS 卸载钩子。
- 预计改动模块：`src/features/settings/`、`src/features/lifecycle/`、
  `src/preferences/`、`src/i18n/`、`src-tauri/src/lifecycle.rs`、
  `src-tauri/src/lib.rs`、`src-tauri/tauri.conf.json`、`src-tauri/installer.nsh`。
- 数据或接口变更：增加自启动状态读取/设置 command；注册值使用当前可执行文件的
  带引号路径及 `--autostart`；Windows 实际注册状态为权威，前端值仅作缓存。
- 性能与资源影响：只在进入设置、切换开关和启动刷新时访问少量注册表数据；登录
  启动不得创建可见窗口或抢占焦点。
- 安全与文件操作风险：路径未正确引用、注册表权限失败、外部禁用状态被误覆盖、
  升级后旧路径残留或卸载未清理会产生失效启动项；不得写入其他用户范围。
- 测试策略：命令生成、状态调和和错误结构单元测试；设置 UI mock 集成测试；非
  管理员 Windows 用户上的启用、停用、重新登录、并发手动启动、升级和卸载测试。
- 替代方案：Tauri autostart 插件可减少注册代码，但仍需证明能读取 Windows 实际
  禁用状态、刷新安装路径并执行卸载清理；计划任务和 HKLM 超出当前用户范围。

### 版本决策

- 是否延期：`No`
- 决策理由：自启动是托盘驻留体验的一部分，来源已明确默认关闭、实际状态权威、
  登录隐藏和单实例竞态合同，可与另外两项在同一生命周期层实现和验证。
- 验收条件：
  - [ ] 新安装和恢复默认时关闭，当前用户不存在 Muller 自启动项。
  - [ ] 开启后重新登录只启动一个隐藏主实例和一个托盘图标，不抢前台焦点。
  - [ ] 关闭后重新登录不启动 Muller，切换开关不额外启动或结束当前进程。
  - [ ] 外部删除或禁用注册项、注册或注销失败时，UI 回到实际状态并显示本地化错误。
  - [ ] 登录启动与手动启动竞态只保留一个实例，且最终窗口可见。
  - [ ] 升级后指向当前路径且无重复项，卸载清理由 Muller 创建的注册项。

## `REQ-0.1.3-003` - 单实例与桌面图标唤出

### 评审输入

- 原始输入：[`01-original-input.md#req-0-1-3-003`](01-original-input.md#req-0-1-3-003)
- 历史 ID：`MUL-LIFE-003`
- 评审日期：`2026-08-13`
- 参与人：`需求提交人（姓名未记录）；文档整理人；技术负责人 TBD`
- 当前结论：`Accepted`
- 优先级：`P0`
- 目标版本或重审条件：`V0.1.3`

### 价值与范围判断

- 用户价值：让桌面图标等入口成为可靠的“启动或唤出”动作，避免重复进程、托盘
  图标和可写工作区，同时保留已有界面与任务状态。
- 问题影响：所有重复启动、快速双击以及登录启动和手动启动竞态都可能受影响；
  当前没有单实例锁或二次启动通知合同。
- 当前版本范围：每个 Windows 用户交互会话的单主实例、启动阶段串行化、手动与
  登录启动意图区分、既有窗口恢复和激活、异常退出后的正常冷启动。
- 非目标：不支持多个独立主实例、多窗口工作区、文件参数或深链接转发、强制结束
  无响应实例按钮；不重新设计桌面快捷方式或开始菜单入口。
- 依赖与阻塞：依赖可靠的实例身份和二次启动 IPC；窗口尚未就绪时必须保存一次
  显示意图；Windows 前台激活限制需要可见性与任务栏提示的降级行为。

### 技术评审

- 建议技术栈：Rust、Tauri 2 `tauri-plugin-single-instance`、Windows 当前会话命名
  同步原语、Tauri WebviewWindow API 和启动参数意图。
- 预计改动模块：`src-tauri/src/lib.rs`、`src-tauri/src/startup_gate.rs`、
  `src-tauri/src/lifecycle.rs`、`src-tauri/Cargo.toml`、`Cargo.lock`，以及启动和窗口
  状态的 Rust/Windows 集成测试。
- 数据或接口变更：二次手动启动向主实例发送“显示”意图；登录启动携带后台意图；
  主窗口未就绪时在主实例内暂存并一次性消费显示请求。
- 性能与资源影响：健康主实例接收请求到窗口可见的耗时应在参考设备上建立基线；
  同步门只覆盖启动初始化，不得长期阻塞正常运行。
- 安全与文件操作风险：启动竞态可能绕过单实例约束；永久锁、死锁或误把登录启动
  当成手动启动会阻止启动或错误抢焦点；不得用模糊进程名作为实例身份。
- 测试策略：命名启动门并发单元测试；冷启动、启动中竞态、隐藏、最小化、后台
  可见、最大化、连续启动和异常退出后的 Windows 多进程测试；工作区状态回归测试。
- 替代方案：仅按进程名查找存在误匹配和竞态；仅使用命名互斥量缺少可靠唤出 IPC；
  仅注册单实例插件而不覆盖主实例初始化窗口可能丢失快速二次启动意图。

### 版本决策

- 是否延期：`No`
- 决策理由：重复实例会破坏托盘和工作区的一致性，也是登录自启动正确性的前置
  能力；来源给出了完整状态矩阵和失败边界。
- 验收条件：
  - [ ] 无进程时手动启动得到一个主实例、主窗口和托盘图标，窗口可见并激活。
  - [ ] 隐藏、最小化、后台可见、最大化时再次启动均复用同一 PID 并正确恢复状态。
  - [ ] 唤出不刷新 WebView、不重置路由或工作区、不取消后台任务。
  - [ ] 窗口未就绪时的二次启动和连续快速启动 10 次最终仍只有一个主实例。
  - [ ] 异常结束旧实例后可正常冷启动；既有实例无响应时不创建第二个可写实例。
  - [ ] 记录健康实例的唤出耗时基线，并验证 Windows 限制抢焦点时的降级提示。
